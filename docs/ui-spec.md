# Hills 介面規格

> 版本：v0.8 · 2026-11-06 · 對應 [feature-plan.md](./feature-plan.md) v1.6
> 本文件定義畫面結構、主要流程與狀態。視覺語言依 D40，見「視覺語言」一節。
> 線框圖以桌機寬度繪製；行動端規則見「行動端」一節。

## 共通規則

- **導覽**：左側固定導覽列（桌機）／底部分頁（行動端）。
- **同步狀態**：視窗右上角固定顯示連線狀態：`● 已同步`、`◐ 同步中`、`○ 離線（變更將於上線後同步）`。
- **離線**：所有 M1 功能在離線時可操作；需要伺服器的動作（取得時間戳、加入組織）顯示「將於上線後完成」。
- **空狀態**：每個列表都要有空狀態說明與主要動作按鈕。
- **確認**：不可逆動作（停用成員、刪除、撤回）一律二次確認；AI 產生的動作以「建議動作卡」呈現，需使用者按「套用」。
- **無障礙**：可完全以鍵盤操作；對比符合 WCAG AA；狀態不只用顏色表達（搭配圖示或文字）。
- **語言**：繁體中文預設，英文可切換；日期依組織語系格式。
- **快捷鍵**：`⌘/Ctrl + K` 全域搜尋與指令、`⌘/Ctrl + Shift + I` 打卡、`⌘/Ctrl + Shift + S` 填寫 Scrum。

## 視覺語言（D40「晴空 · 焦點山」）

> 設計稿：Design 畫布「Hills 設計語言三選一」第四輪（共用基礎、版本二 焦點山）。元件只能用 `tokens.css` 的變數（development-guidelines §4.2）。

- **意象**：山丘 = 辦公地點，原創簡筆角色 = 成員，一座「焦點山」= 今天最需要聚焦的一件事。角色為自繪簡單圖形，頭髮與衣服顏色由成員在「設定 → 個人」選擇；不使用任何既有角色或品牌圖像。
- **字型**：Inter + Noto Sans TC（若系統已安裝），否則用系統字型；安裝檔不打包字型。標題 24–28 / 700，小標 18 / 700，內文 15 / 400（行高 1.6），註解 13。
- **形狀與動態**：4 px 網格；圓角卡片 16、小元件 12、按鈕與名牌 999；觸控目標 ≥ 44 px；動態 180 ms。每頁只有一個主按鈕（晴藍實心），其他為次要樣式。
- **色彩 token（淺色 / 深色）**：

| token | 淺色 | 深色 | 用途 |
|-------|------|------|------|
| `--hills-bg` | `#F3F6FA` 晨霧 | `#0F1620` | 視窗底色 |
| `--hills-surface` | `#FFFFFF` | `#18212D` | 卡片、對話框、名牌 |
| `--hills-text` / `--hills-muted` | `#16202E` / `#3B4656` | `#E8EDF4` / `#A9B4C3` | 文字 |
| `--hills-border` | `#DCE3EC` | `#2A3646` | 邊框、分隔線 |
| `--hills-primary` | `#1F6FEB` 晴藍 | `#4C8DF6` | 主按鈕、選取、「現在」；組織可覆寫（D20） |
| `--hills-on-primary` | `#FFFFFF` | `#0F1620` | 主按鈕上的文字（深色模式白字對比不足，改深色字） |
| `--hills-primary-soft` | `#E6F0FE` 天空霧 | `#1B2B45` | 選取列、聚焦卡底色 |

- **狀態**（顏色 + 徽章形狀 + 角色姿勢 + 文字，四者同時出現；文字色對白底 ≥ 4.5:1）：

| 狀態 | 徽章色 / 文字色 | 徽章形狀 | 角色姿勢 | 名牌附註 |
|------|----------------|---------|---------|---------|
| 上線 | `#1E9E6A` / `#146C48` | 勾 | 拿著筆電 | — |
| 忙碌 | `#E5484D` / `#B42328` | 實心 | 拿著筆電、皺眉 | 至 HH:MM |
| 會議 | `#E5484D` / `#B42328` | 實心 | 頭上對話泡泡 | 至 HH:MM |
| 午休 | `#F07A3A` / `#9A3D0B` | 碗 | 捧著碗筷 | 至 HH:MM |

| 專注 | `#5B6B82` / `#3B4656` | 橫線 | 戴耳機 | 至 HH:MM |
| 休假 | `#7C5CFC` / `#5B3FD6` | 箭頭 | 戴墨鏡、站在雲上 | 休假至 MM/DD |

- **摘要圖卡**：① 標籤（這張卡回答什麼）② 一句結論（含時間或數字）③ 圖解（步驟、倒數環、時間軸、進度條）④ 至多一個動作。
- **日夜**：淺色模式山景右上角是太陽；深色模式改為月亮，月相依當天日期計算（朔望月 29.530589 天，以 2000-01-06 18:14 UTC 的朔為基準，北半球視角：上弦亮面在右）。月亮只是裝飾（不朗讀），不影響其他資訊。
- **減少動態**：跟隨系統「減少動態效果」，角色不走動、登頂彩帶改為靜態圖示；設定中可關閉慶祝效果。
- **清單檢視**：山景都可切換為清單（同樣資訊、同樣順序），鍵盤可依序聚焦每個角色與檢查點；螢幕閱讀器讀出「姓名，狀態，地點，附註」。

## 初次啟動與加入

### 流程

```
啟動 ─┬─ 建立組織 → 貼上 mailbox 連線碼、填寫組織名稱與我的姓名 → 產生復原詞 → 抄寫並驗證 3 個字 → 匯出組織根金鑰備份 → 完成
      ├─ 以邀請碼加入 → 輸入 / 貼上邀請碼、填寫姓名 → 產生復原詞 → 驗證 → 等待管理者核准 → 完成
      ├─ 綁定既有帳號的新裝置 → 輸入組織連線碼 → 顯示綁定碼（文字 + QR）→ 舊裝置「設定 → 我的裝置」貼上 → 兩邊比對 6 位數字 → 舊裝置按「一致」→ 完成
      └─ 以復原詞還原 → 輸入 24 字（英文或繁中皆可）與組織連線碼 → 自動從 mailbox 取回金鑰與資料 → 完成
```

- 流程細節依 technical-design §16.2–16.4；復原詞以介面語言顯示（D38）。
- 個人時區、工作時段在「設定 → 個人」填寫（M1），加入流程不詢問。
- 組織連線碼可由任一成員在「設定 → 組織」複製；mailbox 連線碼由部署者提供（deploy.md）。
- 「建立組織」的 mailbox 連線碼欄位可由建置設定 `VITE_HILLS_DEFAULT_MAILBOX` 預先填入（自架組織在自己的建置環境設定，例如 `apps/desktop/.env.local` 或 CI secret）；repo 不內建任何組織的位址（D20），未設定時欄位為空。使用者仍可修改。

## 首頁（焦點山，D40）

```
┌──┬──────────────────────────────────────────────┬──────────────────┐
│導│ 午安！今天的焦點只有一座山          [⌘K 找人]   │ 下一步 · 第 2/4 步 │
│覽│ 登頂 = 14:00 Windows 驗收完成                   │ (1:20) relay 更新  │
│  │ ┌──────────────────────────────────────────┐ │ [標記完成]  ← 主按鈕│
│  │ │        ⚑ 山頂：14:00 Windows 驗收          │ ├──────────────────┤
│  │ │       ③ 通知測試 · 林小美                  │ │ 等你處理 · 2       │
│  │ │  ② relay 更新 · 你（角色站在這裡）          │ │ 特休核准 / @提及    │
│  │ │            ✓ ① Mac 驗收                   │ ├──────────────────┤
│  │ │ 雲：休假的人                               │ │ 誰快回來（時間軸）   │
│  │ │ 山腳：台北辦公室 · 新竹辦公室 · 遠端（角色）  │ ├──────────────────┤
│  │ └──────────────────────────────────────────┘ │ 今日 Scrum 5 / 8   │
└──┴──────────────────────────────────────────────┴──────────────────┘
```

- **焦點山**：依 feature-plan §5.4 規則（technical-design §16.8）自動選出一件指派給我、或下一步由我負責的任務；步驟（`Task.steps`）沿山路排列為檢查點，顯示負責人與時間；山頂旗子為 `dueAt`。自己的角色站在第一個未完成的步驟。右上「換一座山」可手動選擇其他任務；沒有任務時顯示空狀態：「今天沒有指定的焦點，選一件任務當作今天的山」＋「選擇任務」。
- **完成步驟**：「下一步」卡的主按鈕「標記完成」；角色往上走到下一個檢查點，下一步的負責人收到通知。最後一步完成即「登頂」，短暫彩帶（可關閉、遵守減少動態）。
- **山腳辦公室**：每個辦公室一座小山丘，遠端是有小屋的山丘，休假中的人站在雲上；每個角色下方是名牌（徽章 + 姓名，必要時加附註）。下一步的負責人外圈亮起。人數多時同一座山丘最多顯示 8 個角色，其餘合併為「+N」，點開為清單。
- **點角色**：名片（狀態、地點、目前任務、回來時間）＋「傳訊息」；對方會議、午休或專注中時按鈕改為「敲門」，訊息在對方狀態結束後才通知。
- **誰快回來**：從現在到焦點山期限的時間軸，標出有到期時間的成員；「等你處理」列出核准待辦與 @提及（上限 3 筆，其餘「查看全部」）。
- **權限與隱私**：只顯示成員設定為可見的狀態、地點與目前任務（§5.2 隱私）；不顯示 Wi-Fi 名稱。

## 任務

- 看板（待辦 / 進行中 / 審核 / 完成）與清單兩種檢視，依小組篩選。
- 卡片：標題、負責人頭像、預估時數、關聯計劃、阻礙標示。
- 「開始執行」按鈕把任務設為進行中，並更新自己的 Presence「正在執行」。
- 兩人同時編輯時即時合併，不跳出衝突對話框。

M1 第一批實作範圍（D40）：

- **清單**：依小組分組，每列顯示標題、負責人角色、期限、步驟進度（2 / 4）；焦點任務標示「今天的山」。
- **新增 / 編輯對話框**：標題、小組、負責人、期限（日期 + 時間）、步驟（新增、刪除、上下移動、每步負責人）；儲存後全組即時看到。
- **完成步驟**：清單與首頁都可勾選；勾選最後一步時任務自動變為「完成」。
- 看板、預估時數、關聯計劃、「開始執行」隨計劃功能加入。

## 出勤

### 打卡

```
┌──────────────────────────────────────────────┐
│ 今天 2026-11-05（四）  🏢 台北辦公室            │
│ 上班 08:52 ✓ 已取得時間戳                       │
│ 下班 —                                         │
│ 今日工時 6h 10m / 8h                            │
│                   [ 下班打卡 ]                  │
│ 本月：遲到 1 次 · 加班 3h（已核准）· 特休剩 7 天   │
│ [申請請假] [申請加班] [補打卡]                   │
└──────────────────────────────────────────────┘
```

- 離線打卡顯示「⏳ 時間戳待補」，上線後自動更新。
- 本機與伺服器時間相差過大時顯示警示。

### 申請表（請假 / 加班 / 補打卡）

- 請假：假別、起訖（可選半天或小時）、時數自動計算、代理人、事由、附件；顯示該假別剩餘額度與將套用的核准流程（例：「小組負責人 → 管理者」）。
- 加班：起訖、事由、加班費或補休。
- 補打卡：日期、上 / 下班、時間、事由。

### 核准待辦

- 核准者在「出勤 → 待核准」看到列表，可批次核准；退回需填理由。
- 每筆顯示目前第幾層、前一層核准者與意見。

### 工時報表

- 個人：日 / 週 / 月工時、遲到、工時不足、加班、請假。
- 負責人 / 管理者：小組彙總，可匯出 CSV / Excel。

## 報表

- 列表：日報、週報（M1），月報、年報（M5）。
- 報表內容固定四欄（D32）：完成 / 進行中 / 阻礙、OKR 進度、工時與出勤摘要、下期計劃。
- 草稿 → 編輯 → 選擇發佈範圍（預設小組）→ 發佈；可匯出 Markdown / PDF。
- M3 起在頂部加入「AI 摘要」區塊，可重新產生。

## 設定

| 分頁 | 對象 | 內容 |
|------|------|------|
| 個人 | 全員 | 姓名、時區、工作時段、語言、通知、裝置管理、復原詞重新驗證 |
| 組織 | 管理者 | 名稱、Logo、主題色、語言、時區、假日曆、公司 Wi-Fi |
| 成員與小組 | 管理者 | 邀請、待處理加入申請、停用、小組與負責人、到職日 |
| 假勤規則 | 管理者 | 工作規則、假別、特休級距、核准規則 |
| AI（M3） | 管理者 | 雲端模型開關、用量上限、稽核保留 |
| 整合（M3） | 個人 / 管理者 | Google Calendar（個人）、GitHub App（管理者） |

M0 實作範圍：

- **個人**：語言、我的裝置（列表、綁定新裝置、撤銷）、復原詞重新驗證。
- **組織**：名稱（管理者可改）、組織連線碼（全員可複製）、組織根金鑰備份匯出（僅建立者裝置）。
- **成員與小組**：成員列表、產生邀請碼（文字 + QR，可選管理者 / 成員）、尚未使用的邀請、停用成員（二次確認）。加入申請由建立邀請的管理者裝置自動處理，不需手動核准。
- **團隊**：成員、上線狀態、狀態文字；自己可設定狀態與狀態文字；本機閒置 10 分鐘自動「離開」（technical-design §5.3）。

M1 第一批補充（D40）：

- **個人 → 我的角色**：頭髮、衣服、膚色各從固定色盤選擇，旁邊即時預覽角色；儲存後同事約 2 秒內看到。
- **組織 → 辦公室**（管理者）：新增、改名、刪除辦公室；午休時段（開始、結束）。刪除辦公室時，選擇該辦公室的成員改顯示「遠端」。
- **狀態選單**（左下角我的角色）：狀態、回來時間（15 / 30 / 60 分鐘、指定時間、不設定）、地點（各辦公室 / 遠端 / 不顯示）、狀態文字；組織設定的午休時段內，選單最上方出現「開始午休」。

## 檔案分享

> M1（D35、D36）。

### 分享

- 輸入框旁的 📎 選單：**選擇檔案**（可多選）、**選擇資料夾**。
- 選擇資料夾後先顯示摘要：檔案數、總大小、將略過的項目（符號連結、系統檔、無權限檔案），確認後開始上傳。
- 上傳中在輸入框上方顯示佇列：

```
┌──────────────────────────────────────────────────────┐
│ 📁 設計稿（128 個檔案 · 2.3 GB）                        │
│ ▓▓▓▓▓▓▓▓░░░░░░░░  48%  目前：首頁/hero@2x.png          │
│ 加密並上傳中 · 預估剩餘 2 分鐘        [暫停] [取消]      │
└──────────────────────────────────────────────────────┘
```

- 全部上傳完成後才送出訊息；中途關閉 App，下次開啟時詢問「繼續上傳？」。

### 附件卡

```
┌──────────────────────────────────────┐   ┌──────────────────────────────────────┐
│ 📄 季度報告.pdf                        │   │ 📁 設計稿                              │
│ 12.4 MB · 王小明 · 11/05 10:12         │   │ 128 個檔案 · 2.3 GB · 王小明            │
│ [下載]                                 │   │ [全部下載] [選擇檔案…]                  │
└──────────────────────────────────────┘   └──────────────────────────────────────┘
```

### 下載

- 單檔：選擇存放位置 → 進度 → 完成後提供「打開」「在 Finder / 檔案總管中顯示」。
- 資料夾：選擇目標資料夾；「選擇檔案…」以樹狀清單勾選部分檔案。
- 檔名被調整時（Windows 保留名稱、衝突）在完成摘要中列出原名與新名。
- 無法還原（可用分片少於 5）時顯示「檔案目前無法下載，請稍後再試或請寄件者重新分享」。
- 下載完成前檔案以 `.partial` 存在，使用者不會看到不完整的正式檔案。
