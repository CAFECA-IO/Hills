# Hills 介面規格

> 版本：v0.37 · 2026-11-09 · 對應 [feature-plan.md](./feature-plan.md) v1.18
> 本文件定義畫面結構、主要流程與狀態。視覺語言依 D40，見「視覺語言」一節；token、字級、間距等視覺基礎見 [design-system.md](./design-system.md)，畫面使用的通用元件見 [components.md](./components.md)（D45）。
> 線框圖以桌機寬度繪製；行動端規則見「行動端」一節。

## 共通規則

- **導覽**：左側固定導覽列（桌機）／底部分頁（行動端）。
- **同步狀態**：視窗右上角固定顯示連線狀態：`● 已同步`、`◐ 同步中`、`○ 離線（變更將於上線後同步）`。
- **離線**：所有 M1 功能在離線時可操作；需要伺服器的動作（取得時間戳、加入組織）顯示「將於上線後完成」。
- **空狀態**：每個列表都要有空狀態說明與主要動作按鈕；說明上方有空狀態插畫（v0.33，design-system §9）。
- **載入中**（v0.33）：資料還沒載入時顯示骨架動畫（components `Skeleton`），形狀接近即將出現的內容；不要先顯示空狀態，也不用轉圈圖示。
- **Markdown**（v0.35，D55）：所有 Markdown 內容使用 `Markdown` 元件——表格、勾選清單、提示框、標題層級、程式碼區塊（語言 + 複製）、長文目錄；聊天用精簡樣式（`variant="chat"`）。輸入 Markdown 的地方（知識、交付說明、結案報告）用 `MarkdownEditor`：工具列、編輯 / 預覽切換（v0.36：不提供左右並排；預覽與編輯區同寬、同位置，切換時保留捲動位置與游標）。
- **AI 產生的內容**（v0.35，D54）：作者是 AI Agent 的任務、紀錄、報告、知識與訊息都在作者名稱旁標「AI」徽章。
- **確認與通知**（v0.32）：需要使用者確認的動作與需要同意的條文一律用統一的確認對話框（components `ConfirmDialog`，說明支援 Markdown，條文以勾選「我已閱讀並同意」後才能確認）；一定要讀到的通知用通知對話框（`NoticeDialog`，依 info / success / warning / danger 分級）。
- **確認**：不可逆動作（停用成員、刪除、撤回）一律二次確認；AI 產生的動作以「建議動作卡」呈現，需使用者按「套用」。
- **無障礙**：可完全以鍵盤操作；對比符合 WCAG AA；狀態不只用顏色表達（搭配圖示或文字）。
- **語言**：繁體中文預設，英文可切換；日期依組織語系格式。
- **快捷鍵**：`⌘/Ctrl + K` 全域搜尋與指令、`⌘/Ctrl + Shift + I` 打卡、`⌘/Ctrl + Shift + S` 填寫 Scrum。

## 視覺語言（D40「晴空 · 焦點山」）

> 設計稿：Design 畫布「Hills 設計語言三選一」第四輪（共用基礎、版本二 焦點山）。畫面只能組合通用元件（[components.md](./components.md)）與 token（[design-system.md](./design-system.md)），D45。

- **意象**：山丘 = 辦公地點，原創簡筆角色 = 成員，一座「焦點山」= 今天最需要聚焦的一件事。角色為自繪簡單圖形（v0.37，D56：七種角色——男性、女性、貓、狗、大象、羊、老虎，無線條、正常人體比例、捧著筆電；三個部位的顏色由成員在「設定 → 我是誰」選擇）；不使用任何既有角色或品牌圖像。
- **字型**：Inter + Noto Sans TC（若系統已安裝），否則用系統字型；安裝檔不打包字型。字級依 D45：頁面標題 18（≥ 1600 寬 20）、對話框標題 18、卡片標題 16、內文 14、註解與標籤 12、徽章 11（完整表見 design-system §3）。
- **形狀與動態**：4 px 網格；圓角卡片 16、小元件 12、按鈕與名牌 999；觸控目標 ≥ 44 px；動態 180 ms（design-system §4–§7）。每頁只有一個主按鈕（晴藍實心），其他為次要樣式。

## 版面（D43）

設計稿：設計第五輪「適配電腦解析度」。間距、控制項高度、圓角、層級見 design-system §4–§6。

- **整頁不捲動**：外框高度等於視窗高度，App 視窗最小 1280 × 720；只有面板內的清單（訊息、任務、團隊欄、設定內容）各自捲動，捲動條 4 px、滑過才顯示、可用鍵盤聚焦。
- **欄寬**：左側圖示列 76（≥ 1600 寬時 88）、右欄 280（340），中欄佔滿剩餘寬度；間距 12（16）、外距 16（24）。
- **頂列**：頁面標題、副標、頁面動作、⌘K 搜尋、同步狀態都在 52（60）高的頂列。
- **山景**依容器長寬比調整寬度，山居中、山丘平均分布，人物不裁切；字級不隨解析度放大，大螢幕改為多顯示內容（首頁多一張卡、訊息多一個成員與檔案欄）。
- Windows 1920 × 1080 筆電在 150% 縮放下即為 1280 × 720 CSS px。

## 啟動畫面（v0.26）

App 開啟到讀到本機狀態（`app_info`）之前顯示：

- **延遲 200 ms**：200 ms 內讀到就直接進入下一個畫面，不顯示動畫；超過才顯示，讀到後立即切換，不為了播完動畫延長等待。
- **隨機版本**：六個啟動動畫（design-system §9「啟動動畫」）每次隨機一個，不重複上次（本機記錄上次的版本）。
- 畫面置中：插畫、Hills 字標、「山丘上的卡菲卡」、該版本的狀態文字（`role="status"`）。
- 減少動態時顯示該版本的靜態完成畫面；讀取失敗時改為原本的錯誤畫面。

## 初次啟動與加入

### 流程（D41）

```
啟動 ─┬─ 建立組織 → 貼上 mailbox 連線碼、填寫組織名稱與我的姓名 → 以 CAFECA 登入 → 匯出組織根金鑰備份 → 完成
      └─ 加入組織 → 貼上組織連線碼、填寫我的姓名（新裝置可留空）→ 以 CAFECA 登入
            ├─ 不是成員 → 等待管理者核准 → 完成
            └─ 已是成員 → 等待我的其他裝置確認 → 完成
                         └─ 我沒有其他裝置了 → 說明限制 → 以 CAFECA 登入送出還原申請 → 等待管理者核准 → 完成
```

- 流程細節依 technical-design §17；不再有復原詞與邀請碼。
- 是否已是成員由 mailbox 依 CAFECA 帳戶判斷，使用者不需事先選擇「新成員」或「新裝置」。
- 組織連線碼可由任一成員在「設定 → 組織」複製；mailbox 連線碼由部署者提供（deploy.md）。
- 「建立組織」的 mailbox 連線碼欄位可由建置設定 `VITE_HILLS_DEFAULT_MAILBOX` 預先填入（自架組織在自己的建置環境設定，例如 `apps/desktop/.env.local` 或 CI secret）；repo 不內建任何組織的位址（D20），未設定時欄位為空。使用者仍可修改。
- 個人時區、工作時段在「設定 → 個人」填寫（M1），加入流程不詢問。

### 以 CAFECA 登入

```
┌──────────────────────────────────────────────────────────┐
│ 以 CAFECA 登入                                            │
│ 加入「CAFECA」                                            │
│                                                          │
│  ┌──────────┐   確認碼                                    │
│  │ ▓▓ QR ▓▓ │   K7QD-M2XA                                 │
│  │ ▓▓▓▓▓▓▓▓ │   請確認 CAFECA 顯示相同的確認碼後再簽署        │
│  └──────────┘                                            │
│  用手機上的 CAFECA 掃描                                     │
│                                                          │
│  [在這台電腦開啟 CAFECA]                       [取消]       │
│  ⏳ 等待 CAFECA 回應…（9:32）                              │
└──────────────────────────────────────────────────────────┘
```

- QR 與「在這台電腦開啟」是同一個登入連結（technical-design §17.2），結果經 CAFECA 中繼回傳，兩種方式都不需要再回到 Hills 操作。
- 確認碼以大字、等寬字型顯示；倒數顯示請求剩餘有效時間（最長 10 分鐘），到期後顯示「已逾時」與「重新產生」。
- CAFECA 拒絕時顯示「已在 CAFECA 取消登入」與「重試」；驗證失敗（簽章無效、身分恢復中）顯示原因與「重試」。
- 登入成功後顯示 CAFECA 代稱（或帳戶縮寫 `0x1234…abcd`）。
- **開發測試模式**（D44，只在 debug 建置）：建立與加入表單多一個選填欄位「測試帳號（開發用）」與說明「不經 CAFECA 驗證，只能用於測試」；填寫後按鈕改為「以測試帳號繼續」，略過 QR 與確認碼，直接進入等待核准、等待本人裝置或完成；還原沿用同一測試帳號。mailbox 未開啟測試模式時顯示錯誤。

### 等待核准

- **加入**：「已送出加入申請，管理者上線後會完成加入」，顯示代稱與確認碼；被拒絕時顯示「管理者未核准這次申請」與「回到開始」。
- **新裝置**：「請在你的其他裝置上保持 Hills 開啟，會自動完成」；10 分鐘未完成時顯示「我沒有其他裝置了」。
- **還原**：送出前說明「還原會換發新的成員金鑰：小組、對話資料會由其他成員重新分享給你；只有你自己能看的私人資料無法還原」，勾選「我了解」後才送出。

## 首頁（焦點山，D40）

```
┌──┬──────────────────────────────────────────────┬──────────────────┐
│導│ 午安！今天的焦點只有一座山          [⌘K 找人]   │ 下一步 · 第 2/4 步 │
│覽│ 登頂 = 14:00 Windows 驗收完成                   │ (1:20) relay 更新  │
│  │ ┌──────────────────────────────────────────┐ │ [標記完成]  ← 主按鈕│
│  │ │        ⚑ 山頂：14:00 Windows 驗收          │ ├──────────────────┤
│  │ │       ③ 通知測試 · 林小美                  │ │ 等你處理 · 2       │
│  │ │  ② relay 更新 · 你（角色站在這裡）          │ │ 特休核准 / @提及    │
│  │ │            ✓ ① Mac 驗收                   │ ├──────────────────┤
│  │ │ 雲：休假的人                               │ │ 誰快回來（時間軸）   │
│  │ │ 山腳：台北辦公室 · 新竹辦公室 · 遠端（角色）  │ ├──────────────────┤
│  │ └──────────────────────────────────────────┘ │ 今日 Scrum 5 / 8   │
└──┴──────────────────────────────────────────────┴──────────────────┘
```

- **焦點山**：依 feature-plan §5.4 規則（technical-design §16.8）自動選出一件指派給我、或下一步由我負責的任務；步驟（`Task.steps`）沿山路排列為檢查點，顯示負責人與時間；山頂旗子為 `dueAt`。自己的角色站在第一個未完成的步驟。右上「換一座山」可手動選擇其他任務；沒有任務時顯示空狀態：「今天沒有指定的焦點，選一件任務當作今天的山」＋「選擇任務」。
- **完成步驟**：「下一步」卡的主按鈕「標記完成」；角色往上走到下一個檢查點，下一步的負責人收到通知。最後一步完成即「登頂」，短暫彩帶（可關閉、遵守減少動態）。
- **山腳辦公室**：每個辦公室一座小山丘，遠端是有小屋的山丘，休假中的人站在雲上；每個角色下方是名牌（徽章 + 姓名，必要時加附註）。下一步的負責人外圈亮起。人數多時同一座山丘最多顯示 8 個角色，其餘合併為「+N」，點開為清單。
- **點角色**：名片（狀態、地點、目前任務、回來時間）＋「傳訊息」；對方會議、午休或專注中時按鈕改為「敲門」，訊息在對方狀態結束後才通知。
- **誰快回來**：從現在到焦點山期限的時間軸，標出有到期時間的成員；「等你處理」列出核准待辦與 @提及（上限 3 筆，其餘「查看全部」）。
- **權限與隱私**：只顯示成員設定為可見的狀態、地點與目前任務（§5.2 隱私）；不顯示 Wi-Fi 名稱。

### 規劃精靈（C2–C4、D5）

全頁、置中 760–820 寬，上方 `Stepper`：**想達成什麼 → 為了團隊哪個方向 → 分到四季 → 確認**（年目標；沒有任何公司方向與小組目標時略過第 2 步）。左上「‹ 上一步 / 回到我的目標」，底部左側狀態文字、右側「上一步」＋主按鈕。Enter 等同主按鈕。

1. **想達成什麼**：「〈年〉年，你最想達成什麼？」大輸入框（必填）＋三個範例 chip（點了填入可再改）；「怎麼知道做到了？（可以先跳過）」最多 5 列文字輸入＋「+ 再加一個標準」——存成目標的「做到的標準」（`criteria`，純文字，不影響進度；進度仍由下層彙總），要用數字衡量時在進階檢視改設關鍵結果；可見度一行「全體成員看得到 · 改成只有我」（預設第一個所屬小組，改成只有我 = 私人）。
2. **為了團隊哪個方向**：「『〈標題〉』是為了團隊的哪個方向？」以 `ChoiceCard` 列出我所屬小組的同年小組目標（附「為了公司『…』」），與標題最相近者（字元 bigram 相似度 ≥ 0.3）標示「標題相近，Hills 建議」並預選；最後一張虛線卡「跟團隊方向無關（團隊頁會顯示為『沒對齊團隊』）」。下方「沒有合適的？直接選公司方向 ›」展開公司方向卡片。
3. **分到四季**：第一季…第四季各一列（期間說明 1–3 月…；規劃今年時已過的季不列），輸入框（可空），下方「幫助達成：」以 chip 選擇第 1 步的標準（多選、可不選；存成季目標的 `helps`，只用於顯示「幫助：…」）。底部「已填 N 季」。
4. **確認**：樹狀預覽（年 → 各季），每項「修改」回到對應步驟；空的季顯示「先空著，〈季前一個月月底〉會提醒你」。`details`「更多選項（誰看得到、手動進度）」。主按鈕「建立目標」→ 一次建立年目標與各季目標（季的 `parentId` 為年目標、`alignedGoalId` 沿用年目標），回到首頁並顯示 `Toast`「已建立 1 個年目標、3 個季目標」＋「復原」（10 秒內，刪除剛建立的項目）。

**分到下一層**（季 → 月、月 → 週、年 → 季）：同一個精靈只用第 3、4 步，標題「為了『〈上層〉』，每〈個月 / 週〉要先做什麼？」，列數依期間（3 個月 / 該月的 ISO 週 4–6 週 / 4 季）；已有的子目標以唯讀列顯示在對應期間。

**編輯**（引導式）：點鏈上或清單中的目標開啟單頁表單（同第 1 步欄位＋對齊＋期間唯讀＋「刪除」二次確認），使用 `Dialog`；進階欄位（手動進度、關鍵結果數值）只在進階檢視編輯。我的年 / 季 / 月目標在底部多一個「分到下一層 ›」，隨時開啟分到下一層精靈（不必等提示卡，v0.24）。

### 團隊（D47；設計畫布 D1、D2、D3、D7）

**D1 團隊往哪裡走**（分頁首頁）：頂列年份切換與「2026 第四季 · 已過 43%」。上方每個公司方向一張卡（標題、進度、推動它的小組數）。下方「各小組往哪裡走」每個小組一列：名稱與人數、小組目標與「為了『公司方向』」、進度條、**小方向羅盤**（圓點版）、狀態膠囊「● N 人在路上」「▲ N 人可能偏離」「◷ N 人太久沒更新」（形狀 + 文字 + 顏色；0 人不顯示，v0.24）；點列進入 D2。右欄「你和小組的方向」：只畫我與小組的羅盤＋一句說明（偏幾度、進度與今天應到），下方全公司「N / M 人在路上」與四項原因各幾人（列出姓名）。沒有小組目標的小組顯示「還沒有小組目標」，負責人看到「設定小組方向」。

**D2 每個人往哪裡走**（某小組）：頁首「‹ 團隊」、小組名、人數與負責人、`SegmentedControl`「清單 / 羅盤」。上方小組目標（為了哪個公司方向）、進度與狀態膠囊。清單欄位：成員、這一季的目標（已對齊顯示「為了『…』」，未對齊以警示色顯示「沒有對齊小組或公司方向」）、這週的時間（藍 = 為了團隊方向、灰 = 其他，附百分比；本週沒有完成的事顯示「這週沒有完成任務」）、進度對時程（進度條 + 今天應到的刻度）、最後更新、狀態與原因標籤。可能偏離與太久沒更新的人排在最上面；點列進入 D3。底部說明「可能偏離只是提醒，點名字看原因」「私人目標與私人任務不列入」。

**D7 方向羅盤**（D2 的羅盤檢視）：傾斜的地面上，紫色箭頭與山頂旗是小組方向；每人一條箭頭，角度 = 時間花在哪裡、長度 = 季目標進度；綠色扇形（±45°）是「在路上」的範圍，虛線弧是今天應到的進度。四項檢查的畫法：歪出扇形、虛線箭頭（目標沒對齊）、比虛線弧短很多（落後）、灰色點線（太久沒更新）。箭頭尖端立著成員的角色人像（頭肩像，外框白 = 在路上、橘 + ▲ = 可能偏離、灰 + 時鐘 = 太久沒更新、深色 + 「你」= 我），太近時自動左右錯開。**滑過或用 Tab 聚焦人像**顯示摘要（`Tooltip`）：姓名與狀態、時間（為了團隊的比例與角度）、進度（今天應到）、目標（是否對齊）、最後更新，加一句中性的建議；點人像進入 D3。右欄：「你：偏 N°，在路上 ✓」、和團隊分歧的人（可點）、看圖說明（圖例）。視覺規格見 design-system §9「方向羅盤」。

**D7 的兩個開關**（v0.23，第 4 批）：羅盤上方 `Switch`「四週軌跡」「大家實際走向」，預設都開、記在本機。**四週軌跡**：每個人前 3 週的位置以同色小點（越舊越淡）畫在地面上，以虛點線連到現在的位置，滑過人像的摘要多一行趨勢（例如「四週來越走越偏：15° → 40° → 60° → 72°」或「正在往團隊方向收：36° → 18°」）。**大家實際走向**：所有本週有完成事項的人的方向平均（向量平均），以紫色虛線箭頭畫出並標示「大家實際走向：偏右 6°」；偏 15° 以上時右欄提醒「整組一起偏，可能是小組目標需要調整」。

**負責人的這週重點**：D2 頁首的小組目標下方顯示這週的重點（沒有時，負責人看到「寫這週重點」）；負責人點「編輯」以 `Dialog` 填寫一句話（最多 200 字）。所有成員在週一方向時刻看到。

**D3 某人的方向**：頁首「‹ 小組名」「〈姓名〉的方向」與狀態。左欄「他的努力連到哪裡」：公司方向 → 小組目標 → 他的這一季（每個季目標一列；沒對齊時以警示色虛線標出「這裡沒有連上」）→ 這一週（完成 N 件、為了團隊的比例）。右欄「四項檢查」逐條：✓ 或 ▲、標題、數字依據（例如「這週完成 5 件，1 件連到團隊方向（20%）。門檻：至少一半」）。目標沒對齊且他的小組有小組目標時，主按鈕「建議對齊到『小組目標』」（送出後按鈕改為「已送出建議」），下方說明「建議會送給〈姓名〉，由他決定要不要改；Hills 不會替他修改目標。私人目標與任務不列入，實際情況可能不同」。看自己時標題為「你的方向」，不顯示建議按鈕。

**收到的建議**（我的 · 首頁）：提示卡位置優先顯示「〈姓名〉建議把『季目標』對齊到『小組目標』」＋「套用」（修改該目標的對齊並顯示 `Toast`「已對齊」＋「復原」）＋「不用了」。

**你的方向**（我的 · 首頁右欄，D6）：「你的方向」＋狀態膠囊、只有我與小組的羅盤、一句說明（「你偏 14°：這週 85% 的時間在團隊方向」）、四項檢查的精簡清單（✓ / ▲ + 一句；本週還沒有完成的事時，「時間」一項以中性的「· 這週還沒有完成的事」顯示，不打 ✓，D3 與 D7 右欄同，v0.24）；沒有資料時顯示「這週完成第一件事後就會出現」。這週的任務清單移到其下方。

**週一方向時刻**（v0.23，第 4 批；設計畫布 D8）：每週第一次打開目標頁時（週一起，記在本機）先顯示這一頁，頂列「稍後再看」回到首頁；「你的方向」卡片也有「方向時刻 ›」可以隨時打開。

- 左：「上週你偏 N°，比四週前更集中 / 更分散」＋說明「只有你看得到這一頁；大家在團隊頁看到的是調整後的結果」。下方是只有我與小組的羅盤（較大），畫出四週軌跡，並以半透明的人像標示「調整後」的位置。
- 右：負責人的這週重點（紫底卡片，沒有時不顯示）；「這週想往哪裡走？」列出指派給我、未完成、這週到期或沒有期限、還沒連到週目標的任務（最多 8 件），每件右側 `Select` 選週目標（這週我的週目標，加「跟團隊無關」）；選了之後即時重算「照這樣連上，你這週預計偏 N°」（綠底，或超出範圍時警示色）。按「好，開始這一週」才把選擇寫入任務（`planItemId`），並標示本週已看過；「稍後」不寫入。

- **縮放**（`SegmentedControl` 年 / 季 / 月 / 週）與期間切換「◀ 期間 ▶」「今天」。橫軸是時間，縱向是泳道；今天所在的欄標示「今天」。
- **泳道與格子**（依現有資料模型：只有月 / 週目標能連結上層的關鍵結果，technical-design §16.10）：

  | 縮放 | 欄 | 泳道 | 格子裡 |
  |---|---|---|---|
  | 年 | 12 個月（上方標季） | 這一年的每個年目標 | 它的季目標，橫跨該季的 3 個月 |
  | 季 | 本季的 ISO 週（上方標月） | 焦點季目標的每個關鍵結果，最後是「未連結」 | 它的月目標（`krRef` 決定泳道），橫跨該月的週 |

  | 週 | 週一…週日＋「未排日期」 | 這一週的每個週目標，最後是「未連結週目標」 | 任務（依期限排在那一天）；每天任務超過 3 件時欄頭標示「偏多」 |

- **移動**：把目標拖到另一欄改期間、拖到另一條泳道改上層或推動的關鍵結果（週縮放：拖任務改期限或週目標）。**鍵盤替代**：聚焦卡片後 Alt + ← / → 移到前 / 後一個期間（一天），Alt + ↑ / ↓ 移到上 / 下一條泳道；畫面底部固定提示。同事的目標與私人任務以外的別人任務只能看、不能移。
- **開啟**：點卡片或聚焦後按 E 開啟目標編輯對話框（任務開啟任務對話框）；點兩下或按 Enter 放大到下一層（以它為焦點；任務則開啟任務對話框）。泳道標頭是我的目標時（年 / 月 / 週縮放的目標、季縮放的關鍵結果所屬季目標），點標頭開啟該目標的編輯對話框（v0.31）。
- **一次拆解**（B3）：頂列按鈕，對焦點目標（年縮放為第一個年目標）開啟對話框「把『…』拆成〈下一層〉目標」：每個子期間一區，已有的目標列在上面（含推動的 KR、進度），下方空白列輸入標題與「推動的關鍵結果」（`Select`，季 → 月時才有），打完按 Enter 會再加一列；底部「拆完之後的關鍵結果覆蓋」列出每個 KR 會有幾個子目標，主按鈕「建立 N 個〈層級〉目標」。可見度與對齊沿用焦點目標。
- 「只看我的」開關（`Switch`）移到頂列（關閉時一併顯示同事的目標，唯讀，標示姓名）。

**目標編輯對話框**（v0.17；路線圖與引導式「看全部目標」共用）：標題為「新增目標」/「編輯目標」。欄位依序：
1. **層級 + 期間**（同一列；層級只有年 / 季 / 月 / 週，D46；編輯既有目標時層級不可改）。期間依層級用選擇器，不手打：年 = 年份；季 = 年份 + Q1–Q4；月 = 年份 + 1–12 月；週 = 年份 + 週次（選項標示「W45 · 11/2–11/8」，ISO 週）。年份選項為今年的前 1 年到後 2 年（另含目前值）。換層級時，原期間包含目前檢視的日期就用該日所在的期間（例如年 2026 → 季 Q4），否則取原期間的第一天。
2. **對齊上層**（上一層中包含此期間的項目）。
3. **標題**（必填，標籤標示「必填」，開啟時聚焦）。
4. **連結關鍵結果**（月 / 週，對齊的上層有關鍵結果時）。
5. **可見度**（私人 / 小組〈選一個所屬小組〉/ 全組織，預設第一個所屬小組）；下方說明依選項顯示「小組成員看得到」「只有你看得到」「組織內所有人看得到」。
6. **關鍵結果**（年 / 季，最多 5 個：名稱、起始值、目標值、目前值、單位）；說明「進度依關鍵結果平均計算；沒有關鍵結果時依對齊的子目標」（technical-design §16.10），沒有關鍵結果時顯示空狀態。
7. **手動設定進度**（勾選後輸入 0–100）；說明「勾選後以這個數值為準，不再自動計算；取消勾選即回到自動」。
- 「儲存」不因欄位未填而停用；按下時若標題空白，在標題欄顯示「請填寫此欄」並聚焦。
- 編輯既有目標時左下角有「刪除」（`ConfirmButton`，說明「對齊它的子目標會保留但不再對齊」，v0.31）。
- 有未儲存的修改時，按 Esc 或點對話框外不直接關閉，對話框底部詢問「放棄未儲存的修改？〔放棄〕〔繼續編輯〕」；按「取消」直接關閉。
- 待後續：關鍵結果每週進度趨勢圖、AI 拆解（M3）、回顧表單。

- 「新增 AI Agent」對話框：名稱、用途、負責人、加入小組、它可以（更新指派給它的任務：固定勾選；寫知識；在所屬小組對話回報；讀取全組織公開的目標與知識）→ 產生配對碼（10 分鐘）與指令 `hills-agent pair …`，配對完成後自動關閉並出現在列表。
- 「管理」：改名稱、用途、範圍；停用（`ConfirmDialog` danger：「停用後它無法再存取，所屬小組會輪替金鑰。」）。

- 分派板上 Agent 欄的欄頭顯示「執行中 N · 佇列 N · 最後回報」，不顯示偏重；已暫停的欄半透明並註明「不會領取新任務」。

### 小組（D49，v0.28）

**設定 → 成員與小組 → 小組卡**：管理者看到全部小組；不是管理者的負責人看到自己負責的小組（分頁只顯示這張卡）；其他成員顯示「只有管理者可以管理成員」。

```
┌ 小組 ─────────────────────────────────── [+ 建立小組] ┐
│ 產品小組   5 人 · 負責人 王小明                 [管理] │
│ 工程小組   8 人 · 負責人 陳小華 · 金鑰交接中      [管理] │
│ ▸ 已封存（1）                                         │
└──────────────────────────────────────────────────────┘
```

- 每列：名稱、人數、負責人（多位以「、」分隔，沒有時「尚無負責人」）；本人是成員卻還沒收到小組金鑰時加 `Badge`「金鑰交接中」，滑過說明「等小組成員上線後自動取得」。
- **建立小組**（管理者）：`Dialog` 輸入名稱（1–40 字），從組織成員勾選成員（至少一位）並標記負責人，「建立」。
- **管理**：`Dialog` 顯示成員清單，每列「負責人」勾選與「移出」；下方「加入成員」從尚未在小組的成員選擇。儲存時有人被移出，以二次確認說明「對方將看不到之後的小組內容；已同步的內容無法收回」。說明文字：「新成員要等一位小組成員上線，才能讀到小組內容。請至少留一位已持有金鑰的成員。」
- 管理者另有「改名」與「封存」（二次確認：「封存後不出現在選單與小組頁，資料保留，可取消封存」）；已封存的小組摺疊在列表最下方，可「取消封存」。
- 負責人不能改名、封存或建立小組。
- 錯誤（例如名單空白、負責人不是成員、權限不足）以 `ErrorText` 顯示在對話框內。

## 檔案分享

> M1（D35、D36）。

### 分享

- 輸入框旁的 📎 選單：**選擇檔案**（可多選）、**選擇資料夾**。
- 選擇資料夾後先顯示摘要：檔案數、總大小、將略過的項目（符號連結、系統檔、無權限檔案），確認後開始上傳。
- 上傳中在輸入框上方顯示佇列：

```
┌──────────────────────────────────────────────────────┐
│ 📁 設計稿（128 個檔案 · 2.3 GB）                        │
│ ▓▓▓▓▓▓▓▓░░░░░░░░  48%  目前：首頁/hero@2x.png          │
│ 加密並上傳中 · 預估剩餘 2 分鐘        [暫停] [取消]      │
└──────────────────────────────────────────────────────┘
```

- 全部上傳完成後才送出訊息；中途關閉 App，下次開啟時詢問「繼續上傳？」。

### 附件卡

```
┌──────────────────────────────────────┐   ┌──────────────────────────────────────┐
│ 📄 季度報告.pdf                        │   │ 📁 設計稿                              │
│ 12.4 MB · 王小明 · 11/05 10:12         │   │ 128 個檔案 · 2.3 GB · 王小明            │
│ [下載]                                 │   │ [全部下載] [選擇檔案…]                  │
└──────────────────────────────────────┘   └──────────────────────────────────────┘
```

### 下載

- 單檔：選擇存放位置 → 進度 → 完成後提供「打開」「在 Finder / 檔案總管中顯示」。
- 資料夾：選擇目標資料夾；「選擇檔案…」以樹狀清單勾選部分檔案。
- 檔名被調整時（Windows 保留名稱、衝突）在完成摘要中列出原名與新名。
- 無法還原（可用分片少於 5）時顯示「檔案目前無法下載，請稍後再試或請寄件者重新分享」。
- 下載完成前檔案以 `.partial` 存在，使用者不會看到不完整的正式檔案。
